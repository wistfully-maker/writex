# Enhanced Write Chapter

Start with the legal WriteX Base chapter workflow.

## 1. Compile context

Collect:
- POV-safe continuity;
- Book/Volume structural coordinates;
- LongFormChapterDirective;
- active Reader Questions;
- relevant character magnetism state;
- relevant relationship state/debts;
- relevant mystery state;
- active emotional debts;
- StyleHistory diagnostics.

## 2. Build EnhancementBundle

Use `references/enhancement/router.md`.

Only activate modules that perform real work this chapter.

Example:

```yaml
enhancement_bundle:
  reader_drive:
    move_question: q17
  character_magnetism:
    event: independent_agency
  relationship_tension: null
  type_pleasure:
    mystery_move: narrowed_question
  emotional_orchestration: null
  prose:
    mode: competence_mode
```

## 3. Scene planning

For every scene, state:
- scene purpose;
- POV;
- foreground enhancement modules (max 2 default);
- state change;
- primary prose mode;
- narrative distance;
- 2–4 description anchors;
- dominant metaphor source/domain;
- dialogue function;
- ending function.

## 4. Competitive drafting

Use three candidates with the same facts:

A. `voice_and_relationship_truth`
- strongest character-saturated narration;
- clearest needs, subtext, and independent agency.

B. `scene_propulsion_and_visual_clarity`
- strongest spatial clarity, operational worldbuilding, competence, and reader drive.

C. `subtext_and_emotional_delay`
- strongest restraint, debt timing, afterimage setup, and indirect emotional meaning.

Do not make any candidate more "literary" by adding decorative metaphors.

## 5. Enhanced review

Review only activated modules.

### Always review prose
- POV ownership;
- sentence rhythm;
- selective description;
- dialogue identity;
- ending restraint.

### Review active modules
Examples:
- reveal -> consequence + reframe;
- repair -> repair cost;
- major loss -> prior deposits + residue;
- magnetism refresh -> genuinely new understanding;
- reader question -> advanced/narrowed/paid, not merely restated.

## 6. Revision

Revision plan must distinguish:
- causal failure;
- structural failure;
- reader-drive failure;
- emotional-timing failure;
- prose-control failure.

Never fix a causal failure with prettier prose.

## 7. Human gate

Ready chapter remains a proposal until explicit human acceptance.
Only after acceptance:
- apply base continuity;
- update enhanced ledgers;
- update CarrierRegistry / StyleHistory;
- risk scan.
