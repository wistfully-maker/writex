# WriteX 最小文学模型评测设计

状态：用户已于 2026-09-07 确认，进入实现；首轮仅 DeepSeek Flash 与 Pro。

## 目标与已确认选择

用可复现的小规模实验选择值得进入 WriteX 创作工作流的模型。按用户确认，本阶段仅测试 deepseek-v4-flash 与 deepseek-v4-pro，使用已有 DeepSeek API 凭据。OpenAI 模型、API 适配器及 ChatGPT 人工导入均延后，不属于本阶段范围。API 模型标识由配置提供，运行前核验账户可用性。

由用户匿名盲选决定偏好。LLM 只提供五项诊断证据，不替代用户决定。评价依据：受欢迎的小说 = 永恒情感 × 新鲜处境 × 艰难选择 × 人物真实性 × 叙事控制。五项权重与最低门槛均可配置，重算评分无需重新生成。

本实验测量模型在固定创作任务下的表现，不证明可稳定完成长篇或达到投稿质量。

## 评测集

采用三个独立场景及一组连续续写，保持中文、克制抒情、具体动作与潜台词等既定创作方向，题目使用原创材料。

1. 重逢场景：多年未见的两人因一件共同隐瞒的旧事重逢；测情感、人物动机和潜台词。
2. 选择场景：人物必须在两项无法兼得的责任之间行动，代价在场景中实际发生；测处境、选择和因果。
3. 信息揭示场景：有限视角下逐渐显露一个改变人物关系的事实；测节奏、伏笔和信息控制。
4. 连续续写：相同人物档案、事实表和开篇材料起步，连续生成三段；每个模型接收自己的前文以及相同的阶段任务。测人物、时间线、物件状态及伏笔延续。

每段目标 800–1200 中文字。每模型三篇独立场景加三段续写，共 6 次生成；两个 DeepSeek 模型共 12 次 API 正文生成。上述数量不包含另行估算的诊断调用。首轮每题每模型一个样本，接近或矛盾结果再复测。生成上限与思考额度分开记录，截断结果标记为无效，不作为完整稿评分。

## 盲选与诊断

独立题分别随机排列候选；续写三段作为一组保持同一匿名编号。匿名稿只展示题目与正文，不显示模型、价格、延迟或自动评分。模型映射单独保存，不能混入匿名文件名或元数据；此机制用于防止意外揭盲，不作为访问控制。

用户可排序、选择并列或全部不合格，并写简短原因。提交盲选后展示 LLM 诊断，再揭示模型与用量报告，避免自动评分先入为主。

诊断针对匿名稿，按五项输出证据、问题和可执行修改建议；连续续写另列事实冲突。诊断使用可配置的 DeepSeek API 模型并在报告中披露，报告注明可能的自评及同厂商裁判偏差。五项加权几何评分及各维度门槛沿用现有 quality 包；自动分数不改变人工选择。

## 工程边界与数据

扩展现有 ModelGateway，提供 DeepSeek 适配器及注入式 HTTP 测试替身。评测编排负责固定题目、提示词版本、顺序、续写上下文、保存结果与失败恢复；盲选导出及报告负责匿名映射、人工选择与揭盲。DSH 驱动只承担开发执行职责。

模型配置保存 provider、model、端点、密钥环境变量名称、思考设置与输出上限；密钥值不写入作品、报告或 Git。运行记录保存请求标识、模型返回标识、提示词与配置哈希、时间、状态、正文和可用的 token/cache/reasoning 用量。隐藏推理正文不进入评测产物。

正常测试使用本地替身。真实运行须显式开启 live 模式，先展示计划请求数与按配置价格计算的上界估算。记录价格来源和生效时间；未知用量或价格显示未知，不能当零。预算检查在每次请求前执行，预留失败请求的额度，避免因重试超支。

认证失败立即停止；限流、超时和服务错误记录为失败，首版不自动重发有潜在费用的请求。可显式重试失败项，成功结果保持不变。空正文、截断或结构错误独立报告。加赛生成只在用户盲选表明接近并确认加赛后执行，不由自动分数触发。

## 验收

- 替身端到端测试覆盖两个 DeepSeek 模型的 12 次正文生成、续写上下文隔离、失败恢复、匿名导出、人工选择、诊断与揭盲报告；整个流程仅依赖 DeepSeek API 凭据。
- 匿名产物不泄漏模型映射，评分权重变化不触发模型请求。
- 无 live 标志不产生网络生成请求；缺失凭据、预算不足、截断和失败均有明确状态。
- 实际文学评测的完成以生成有效匿名稿、用户盲选及报告为准；工程测试通过不能替代文学质量结论。

## 开发方式

Codex 完成设计、计划、审核、最终验证及 Git 操作；DSH 使用一个长期命名会话完成本阶段实现与集中返修。相关任务按可验证切片派发，先保存检查点再处理上下文压缩。
